# Plot 3 design: "Broken toaster" (2026-11-19)

**Short version:** Yash's Toaster Bench (pack 0, §1.1) rebuilt as game screens with drawings. A kitchen house holds it, in its own fenced "CHAPTER 1.1" yard east of the farm, reached by a dirt path through a gate in the east fence (2026-11-20). The student finds why the toaster won't toast with at most 3 tests, and learns the 5 steps: Choose → Predict → Run → Commit → Feedback.

Source: `project/from-team/toaster-bench/` (Yash, 2026-11-18). The scoring rules and the 4 × 3 answer key are copied unchanged.

## Screens (one idea each)

| # | Screen | What the student does |
|---|---|---|
| t1 | The toaster won't toast | Sees the kitchen: pale bread, outlet A. Next. |
| t2 | Three ideas, one is true | Outlet A is broken / the toaster is broken / the kitchen has no power. Next. |
| t3 | 1 Choose | Taps one of 4 test cards. Sees tests left (3) and results so far. "Commit now" once a test has run. |
| t4 | 2 Predict | For each idea, taps "works" or "doesn't work". Lock. 1st wrong: a hint. 2nd wrong: the answer is shown. If all ideas still in play predict the same thing: "Pick another test" (free) or "Run it anyway" (costs 1). |
| t5 | 3 Run | The device works or not. The result is shown beside the 3 locked predictions. "Another test" or "Commit". |
| t6 | 4 Commit | A table: tests run × each idea's prediction × result. Under each idea: still possible / ruled out. The conclusion follows from the marks. |
| t7 | 5 Feedback | The hidden fault is revealed. Correct / claimed more / claimed less / mixed / contradicts, per idea. |
| t8 | The loop | The 5 steps as a picture. +50 sun points the first time, star on the kitchen. Play again / Back to farm. |

Back and Farm inside the loop: no Back after a prediction is locked or a test is run. Leaving with Farm keeps the same hidden fault and screen.

## Changed from Yash's version (team to confirm)

1. **No typed reason (≥ 25 characters) and no confidence slider.** Same rule as our intro task: no typing in a tutorial. Yash listed "written reasons are logged" as a property to keep.
2. **The conclusion is derived from the marks**, not picked separately: one idea left → "it is X"; more → "not settled". Yash's separate check that conclusion and marks agree is therefore not needed.
3. **Shorter texts.** Hints, reasons and feedback cut to one line each.
4. **Stage tips always on** (Yash turns them off after round 1).
5. **Fig. 1.6 box labels not shown.** The recap points to Fig. 1.6, p. 14, without quoting the boxes (not checked against the figure image yet).
6. **No per-page JSON copy.** Predictions, runs and verdicts go to the game's shared answer log instead (`EXPORT.md`). Typed reasons and confidence are not recorded (there are none).
